# Showcase preparation and maintenance

Source plan: the owner's authorized public-portfolio export request, recorded in [governance/DECISIONS.md](../governance/DECISIONS.md).

Derived from: a curated application snapshot of the private vocabulary project, plus the accepted local-demo, privacy, and rights boundaries. Private Git history is not inherited.

Scope: retain the application and useful tests; provide a runnable synthetic local demo, public-safe documentation, explicit asset terms, a compact governance package, and a fresh publication history.

Non-Scope: publishing the private repository or its history; importing real study data; connecting cloud accounts; enabling paid providers; deploying an app; recreating operational scripts; adding confidential per-person authorization.

Exit criteria: fresh dependency installation and relevant local checks pass; the local demo is inspected with synthetic data; public files and assets pass the bounded secret/privacy review; rights are documented; only the approved showcase is published. Any unobserved claim remains explicitly pending.

1. Reconcile the retained runtime, safe commands, synthetic sample, and separate browser storage namespace.
2. Validate with a fresh install, the aggregate local check, and a build; record exact results and skipped integration coverage in [VALIDATION.md](VALIDATION.md).
3. Verify the local demo through a functional browser walkthrough with synthetic content. The owner has deferred screenshots because a separate UI redesign is planned; no screenshot deliverable is required.
4. Review the final file inventory, secret scan, privacy scope, and rights notices. Confirm the new history contains only the curated showcase.
5. Publish within the owner's authorization, then record the observed remote state without implying a deployment.

## 3. Maintenance boundary

Future work starts from the same local-only default. Material changes update affected owners and tests. Connecting services is a separate decision requiring target identities, credential separation, spending limits, data policy, and deployment protection. Public repository visibility cannot substitute for any of those controls.
